# Quick Task 260513-k37: Improve Web Product Tiles + Add Product Detail Page Summary

**One-liner:** Redesign every web product tile as a full-tile link to a per-item detail page (`/registry/:id/item/:itemId`) and extend that page with three new browse-state branches — available (Reserve CTA via direct mutation), reserved-by-other (view-only, no reserver name), and purchased (view-only, no giver name). Preserves the existing reserved-by-me/expired/release/confirm flows unchanged, with D-06 enforced everywhere.

## What Changed

### Task 1 — ItemCard tile redesign (COMPLETE)

**`web/src/features/registry/ItemCard.tsx`**
- Wrapped the entire tile in `<Link to=/registry/{registryId}/item/{item.id}>` so every status (available, reserved, purchased) navigates to the detail page on click.
- Body restructured as a vertical stack (gap-2, p-4):
  - Shop line — `MonoCaption` micro/faint = `merchantDomain` raw (uppercase via mono caps)
  - Product name `h3` — truncated to 60 chars with trailing `...` when longer (and `trimEnd()` before the ellipsis so no whitespace ever immediately precedes `...`)
  - Price — `font-semibold` with currency rendered as small mono on the side
- Removed the inline Reserve CTA (`reserveSlot` prop and reserve-slot block). Whole tile is the affordance now.
- Reserved-by-me banner kept; click handler calls `e.preventDefault(); e.stopPropagation()` before invoking `onReservedByMeClick` so the surrounding Link does not double-navigate.
- Purchased tiles still apply `opacity-[0.55]` AND remain wrapped in a Link (clickable).
- Added `aria-label` reading `web_pill.tile_aria` for screen readers.
- Exported helper `truncateTitle(title, limit=60)` for reuse and unit-testability.

**`web/src/features/registry/ItemGrid.tsx`**
- Removed the `renderReserve?: (item: Item) => React.ReactNode` prop and stopped forwarding it.
- Added required `registryId: string` prop, forwarded to each `ItemCard`.
- Kept `renderReservedByMeClick`.

**`web/src/features/registry/SkeletonCard.tsx`**
- Replaced the title + inline price-row skeleton with three stacked bars matching the new shop / name / price hierarchy.

**`web/src/pages/RegistryPage.tsx`**
- Stopped passing `renderReserve` to `<ItemGrid>`.
- Now passes `registryId={registryQ.data!.id}`.
- Removed the unused `import ReserveButton from '../features/reservation/ReserveButton'` line.

### Task 2 — ItemReservePage browse-state branches + direct Reserve mutation (COMPLETE)

**`web/src/pages/ItemReservePage.tsx`** — new state machine (priority order, top to bottom — first match wins):

| # | Condition | Branch |
|---|-----------|--------|
| 1 | `!id || !itemId` | `null` (router safety) |
| 2 | `items === undefined` OR `lookupStatus in {idle, loading}` | loading |
| 3 | `!item` | `item-reserve-not-found` |
| 4 | `active && countdown.expired` | `item-reserve-expired` |
| 5 | `active` | `item-reserve-detail` (reserved-by-me happy path — UNCHANGED) |
| 6 | `!active && status === 'available'` | **NEW** `item-reserve-available` (Reserve CTA) |
| 7 | `!active && status === 'reserved'` | **NEW** `item-reserve-reserved-by-other` (view-only) |
| 8 | `!active && status === 'purchased'` | **NEW** `item-reserve-purchased` (view-only) |
| 9 | fallback (unreachable for any valid `ItemStatus`) | legacy `item-reserve-not-yours` |

**Reserve flow (BROWSE_AVAILABLE — DIRECT mutation per user decision):**
- Wired `useCreateReservation` directly inside `ItemReservePage` with `onSuccess`:
  - Calls `useActiveReservation().set(...)` to seed the context with the new reservation.
  - Shows `reservation.success` toast.
  - Does **NOT** call `navigate(...)` — the URL is already `/registry/:id/item/:itemId`; on the next render `useReservationForItem` hydrates `active` and the reserved-by-me happy path (state 5) takes over naturally.
- `onError`: existing `mapHttpsErrorToI18nKey` toast pattern.
- Click handler mirrors `ReserveButton.handleClick` exactly so derivation stays in sync:
  - **Signed-in:** `giverName = user.displayName || email.split('@')[0] || 'Guest'`, `giverEmail = user.email ?? ''`, `giverId = user.uid` → `mutate(...)`.
  - **Guest with stored identity:** `giverName = ${first} ${last}`.trim(), `giverEmail = identity.email`, `giverId = null` → `mutate(...)`.
  - **Anonymous-no-identity (only round-trip path):** `navigate(/registry/:id?autoReserveItemId=:itemId)`. RegistryPage's existing GuestIdentityModal + auto-reserve effect handle identity capture and on success navigate back to `/registry/:id/item/:itemId`.
- Disabled + spinner shown while `mutation.isPending`.

**Shared inline helpers (no new files per spec):**
- `BrowseShell` — TopNav + back-to-registry link + Footer chrome used by all three browse branches.
- `ItemDetailHero` — view-only hero card with image / Pill / shop / FULL untruncated name / price. NEVER renders reserver/giver name (D-06).
- `NotesBlock` — owner notes section labelled with `web_reserve.item_page.notes_label`. Omitted entirely when `item.notes` is null.
