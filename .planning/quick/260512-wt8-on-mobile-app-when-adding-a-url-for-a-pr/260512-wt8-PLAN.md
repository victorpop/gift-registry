<objective>
Make the Android "Add Registry Item / Paste URL" flow auto-fetch product details when the user types or pastes a valid http(s) URL, with a ~700ms debounce, in-flight cancellation, and de-dup against the last fetched URL. The existing trailing icon button is kept as a manual-retry affordance (useful after an error) but its rotational `Icons.Default.Refresh` icon is replaced with a fetch-semantic `Icons.Outlined.CloudDownload` and given a localized contentDescription.

Auto-fetch matches modern UX expectations (Notion, Linear, Slack all auto-resolve URLs on paste). The Refresh icon is misleading because it suggests "reload the same thing" when the actual action is "fetch metadata from a URL."

Output: One ViewModel change wiring an auto-fetch pipeline, one Screen change for the icon swap + localized contentDescription, two strings entries (en + ro), and one test file pinning the debounce/dedup/cancellation/validity-gate contracts.

    ```kotlin
        // quick-260512-wt8: Auto-fetch on URL change.
        //
        //   - drop(1)             skip the initial "" emission from MutableStateFlow
        //   - debounce(700)       wait until typing/pasting settles
        //   - distinctUntilChanged   suppress redundant identical re-emissions
        //   - filter(isValid)     gate on http/https + non-blank host
        //   - collectLatest       cancel any in-flight fetch when a new url arrives
        //
        // De-dup against lastFetchedUrl happens INSIDE the collector, AFTER
        // debounce, so we don't refetch what we just fetched.
        viewModelScope.launch {
            url
                .drop(1)
                .debounce(700)
                .distinctUntilChanged()
                .collectLatest { current ->
                    val trimmed = current.trim()
                    if (!isValidProductUrl(trimmed)) return@collectLatest
                    if (trimmed == lastFetchedUrl) return@collectLatest
                    onFetchMetadata()
                }
        }
    }
    ```
