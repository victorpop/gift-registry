<objective>
Add a per-item reserve-detail route so every active reservation on a registry is reachable by URL — not just the most-recent one. Clicking a reserved-by-me item card navigates to `/registry/:id/item/:itemId`. After any successful reserve, the user is auto-navigated to the same route (replacing the just-removed fk1 auto-open of the retailer URL). The new page mirrors the existing in-page `ReserveDetailSection` visually but is driven by a route-scoped per-item server lookup so it works for the non-most-recent reservation too.

Purpose: today `useActiveReservation` and `hydrateActiveReservation` are single-slot — only the most recent active reservation is visible. With 2+ concurrent reservations, the older one is unreachable. A dedicated per-item URL is the discovery affordance and a deep-linkable surface.

Output:
- New Cloud Function callable `getReservationForItem` (+ unit tests).
- New React hook `useReservationForItem` (+ unit tests).
- New page `ItemReservePage` mounted at `/registry/:id/item/:itemId` (+ component tests).
- Wiring: ItemCard reserved-banner click → navigate; three reserve-success sites in RegistryPage + ReserveButton → navigate; existing scroll-to-anchor handler removed.
- i18n keys for the new page added in EN + RO across both `web/src/i18n/` and `web/i18n/`.
</objective>
