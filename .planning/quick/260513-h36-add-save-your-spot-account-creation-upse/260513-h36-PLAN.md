<critical_design_note>
The user's task spec mentions `linkWithCredential` on an anonymous Firebase user. **This project has NO anonymous Firebase auth path** — `useAuth()` returns `user: null` for guests, and reservations are keyed by `giverEmail` (with `giverId: null`) in the backend (see `useReservationForItem` and `useCreateReservation`).

Therefore: use `signUpEmail(email, password)` from `authProviders.ts` (which calls `createUserWithEmailAndPassword`). After signup, the new Firebase user has the same email as the guest reservation, so:

1. `useAuth().user` flips from `null` to the new User.
2. `useReservationForItem` re-runs because `authReady`/`user` changed; its key includes `effectiveEmail = user.email ?? identity.email`. The email is unchanged, so the same reservation continues to hydrate (the backend match by email still succeeds for guest reservations).
3. The reservation remains visible on the page; no transfer call is required.

This is simpler and more aligned with the existing codebase. **Do not introduce anonymous-auth/linkWithCredential** — it would require backend changes we are not making here.
</critical_design_note>

**Open-condition state.** Derive a boolean `shouldShow` and a `setOpen`/`open` pair as follows:

```tsx
const [modalOpen, setModalOpen] = useState(false)
const dismissedKey = active ? `saveYourSpot.dismissed.${active.reservationId}` : null

// Compute eligibility once active reservation is known.
useEffect(() => {
  if (!active) return                                       // need an active reservation
  if (user) return                                          // signed-in users skip the upsell
  if (!identity?.email) return                              // no email to pre-fill → nothing to upsell
  if (countdown?.expired) return                            // expired state already handled above
  if (!dismissedKey) return
  try {
    if (sessionStorage.getItem(dismissedKey) === '1') return
  } catch { return }                                        // sessionStorage unavailable → fail-closed (don't show)
  setModalOpen(true)
}, [active, user, identity?.email, countdown?.expired, dismissedKey])

function handleDismiss() {
  if (!dismissedKey) return
  try { sessionStorage.setItem(dismissedKey, '1') } catch { /* ignore */ }
}

function handleSaveYourSpotSuccess() {
  showToast(t('save_your_spot.success_toast'), 'success')
  // Persist dismissal so the modal doesn't reopen if useAuth re-renders before unmount.
  if (dismissedKey) {
    try { sessionStorage.setItem(dismissedKey, '1') } catch { /* ignore */ }
  }
}
```

Note: place the `useEffect` for eligibility **before** the early returns (loading / not-found / not-yours / expired), per React's rules of hooks. Wrap the body of the effect with the existing guards (the effect can run unconditionally; the inner `if (!active) return` handles the missing-data branches). Same for `useState`. Existing hooks in this file (`useEffect` blocks for release/status) are already declared above the early returns — follow the same convention.
