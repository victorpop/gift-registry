## ⚠ Flow Pivot (Task 3)

The initial Tasks 1+2 placed the SaveYourSpotModal **after** a successful guest reservation (on ItemReservePage). User verification surfaced that the intent was the opposite: the modal should appear **before** the reservation, replacing the existing GuestIdentityModal as the primary modal a guest sees when tapping Reserve.

Restructure (commit `2d2bcdb`):

- **SaveYourSpotModal** now collects `firstName + lastName + email + password` in one form. Pre-fills from `useGuestIdentity` (localStorage).
  - Primary "Create account & reserve →": validates all fields → `signUpEmail` → parent reserves under the new Firebase user.
  - Secondary "Continue as guest": validates name+email only (no password) → parent reserves as guest.
  - Persists name/email to `useGuestIdentity` on either path (so subsequent reserves pre-fill).
- **ReserveButton.tsx** now opens `SaveYourSpotModal` for anonymous users (was `GuestIdentityModal`). Signed-in users still skip the modal entirely.
- **ItemReservePage.tsx**: removed the post-reservation mount, eligibility `useEffect`, and `sessionStorage` dismissal — no longer relevant.
- **i18n**: replaced post-reservation copy ("✓ RESERVED", "29:58 left", "Using {email} from your guest reservation") with pre-reservation copy ("Reserving {itemName}", "Create account & reserve →", "Continue as guest"). 21 keys, EN/RO parity verified.
- **GuestIdentityModal kept** — still used by `RegistryPage` for the deep-link `?autoReserve=…` path. Not deleted.
- **Tests**: 2 ReserveButton tests updated for new modal title/CTAs; 3 new tests added for account-creation path (success, weak-password, email-already-in-use). Suite: **144/144 passing**.

## Accomplishments

- New `SaveYourSpotModal` component (Radix Dialog + react-hook-form + zod), mirroring the structural patterns of `GuestIdentityModal` and `AuthModal`.
- `save_your_spot.*` i18n block added to both `en.json` and `ro.json` with identical key sets and project-tone Romanian translations.
- Wired into `ItemReservePage` with an eligibility `useEffect` that opens the modal exactly once per guest reservation (gated on: active reservation, `user === null`, `identity.email` present, countdown not expired, no sessionStorage dismissal flag).
- Firebase auth errors mapped to user-friendly i18n strings (`auth/email-already-in-use`, `auth/weak-password`, `auth/invalid-email`, generic fallback).
- Success path shows a toast (`save_your_spot.success_toast`), closes the modal, and persists the dismissal flag so the modal doesn't re-open during the brief window before `useAuth` re-renders.
