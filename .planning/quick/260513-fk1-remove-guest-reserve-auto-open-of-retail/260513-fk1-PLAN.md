<objective>
Stop the web fallback from auto-opening the retailer tab on successful reservation. The retailer URL should only open when the user explicitly clicks the "Continue to retailer" CTA in `StickyReserveBanner`.

Purpose: Reverses WEB-D-07's "redirect to retailer on success" decision because users were getting jumped to an external site without consent. The deliberate, user-initiated path through `StickyReserveBanner` already exists and is the correct UX. The current behaviour is jarring (especially for guests) and is the most-recently-reported complaint.

Output:
- `useCreateReservation` becomes a pure data mutator with no window.open side effect.
- Existing test inverted: it now asserts window.open is NEVER called.
- i18n success toast strings updated to drop the "Redirecting to retailer…" wording.
- UI-SPEC line for "Reservation success toast" updated to reflect the new copy.
- Human-verify checkpoint confirms guest + signed-in flows + auto-reserve-from-deep-link flow all stay on the registry page.
</objective>
