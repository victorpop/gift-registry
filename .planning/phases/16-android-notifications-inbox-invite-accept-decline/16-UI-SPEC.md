# Phase 16 — UI Design Contract

> Visual and interaction contract for the Android notifications inbox re-skin + invite Accept/Decline surfaces. Generated by gsd-ui-researcher from CONTEXT.md (28 locked decisions D-01..D-28), RESEARCH.md (11 patterns + 8 pitfalls), and the GiftMaison theme inventory (Phase 8: 13 colors, 10 typography roles, 7 shape radii, 10 spacing tokens, 3 shadows). Verified against `app/src/main/java/com/giftregistry/ui/theme/*` and `app/src/main/java/com/giftregistry/ui/notifications/NotificationsScreen.kt`.

|-------|-------|----------------|

| `spacing.gap6` | 6 dp | (Not used in Phase 16) |
| `spacing.gap8` | 8 dp | Time-metadata to body gap; warn-banner icon-to-text gap |
| `spacing.gap10` | 10 dp | (Not used in Phase 16 — superseded by gap8 / gap16 / gap20 at card scale) |
| `spacing.gap12` | 12 dp | Sheet CTA button vertical padding inset (matches existing M3 button defaults — declarative only) |
| `spacing.gap14` | 14 dp | NotificationCard vertical padding (top/bottom) |

**Vertical rhythm inside InviteResponseSheet:**

```

[HeroImageOrPlaceholder — 180 dp tall, full bleed]

spacing.gap8  (8 dp)
[Decline button — full-width outlined]
spacing.gap20 (20 dp bottom inset; system inset added by ModalBottomSheet)
```

**NotificationCard internal rhythm (re-skinned per D-09):**

```
[card row]
  16 dp horizontal padding (spacing.gap16)
  14 dp vertical padding (spacing.gap14)
  [Leading icon 24 dp]
  12 dp gap to text column (spacing.gap12 — M3 default for icon-text gap; matches existing card)
  [Text column]
    [Row: Title (bodyL) + spacer-fill + MonoCaps timestamp + (optional) 6 dp accent dot if unread]

```

Exceptions:
- Inbox empty state Text is vertically centred in the Scaffold body; no explicit gap tokens (Compose `Alignment.Center`).
- The hero image inside the sheet bleeds to the sheet edges (no horizontal padding inside the hero box); horizontal padding of 20 dp applies to all elements BELOW the hero.
- AlertDialog (Decline confirmation, D-03) uses Material3 dialog defaults — no GiftMaison spacing overrides; this is M3 vanilla per CONTEXT.md "no new component needed".

## Color

Phase 16 consumes existing `GiftMaisonColors` Housewarming palette declared in `app/src/main/java/com/giftregistry/ui/theme/GiftMaisonColors.kt`. No new color is introduced. The 60/30/10 dominant/secondary/accent split maps to GiftMaison tokens as follows:

| Role | Token | Value (sRGB) | Phase 16 Usage |
|------|-------|--------------|----------------|
| Dominant (60%+) | `colors.paper` | #F7F2E9 | Inbox screen background (replaces M3 `surface`); sheet background (replaces M3 `surfaceContainer`); empty-state background |
| Secondary (30%) | `colors.paperDeep` | #EDE5D5 | (Not used in Phase 16 inbox — the re-skin drops M3 Card elevation per D-09 so there is no separate "card surface". Cards become flat strips of `paper` separated by `gm.line` dividers.) |
| Line (structural) | `colors.line` | #DDD4C4 | 1 dp dividers between notification cards (replaces M3 Card elevation per D-09) |
| Text — primary | `colors.ink` | #2A2420 | NotificationCard title (unread); sheet title; decline dialog title |
| Text — secondary | `colors.inkSoft` | #6A5E52 | NotificationCard body; NotificationCard title when read (visually muted); sheet event-date metadata |
| Text — tertiary | `colors.inkFaint` | #9C8E7F | (Not used in Phase 16 — `inkSoft` covers all secondary-text needs at the card scale) |
| Accent (10%) | `colors.accent` | #C8623A | **Reserved for**: (1) Sheet registry name (Display L italic), (2) unread accent dot in NotificationCard (6 dp circle), (3) Accept button background (Material3 `Button` with `containerColor = accent`), (4) Decline button outline + text (Material3 `OutlinedButton` with `border` color = `accent` per the "gm.accent text on outlined" handoff convention is rejected — see note below), (5) wordmark period in `GiftMaisonWordmark` top bar (already implemented in Phase 8). |
| Accent Ink | `colors.accentInk` | #FCF8EF | Text color on the Accept button (the cream tone that reads on the terracotta accent) |
| Accent Soft | `colors.accentSoft` | #F3DED0 | (Not used in Phase 16 inbox/sheet — reserved for future selected-tab pills) |
| Second (Olive) | `colors.second` | #4F7050 | (Not used in Phase 16 — was the "Given" status chip color; no Given chips on inbox cards) |
| Second Soft | `colors.secondSoft` | #D7E2CE | (Not used in Phase 16) |
| Success | `colors.ok` | #4F9668 | (Not used in Phase 16 — JOINED confirmation uses the standard ink text color, not a success tint, per the "card visual richness lives in the sheet, not the card" D-02 principle) |
| Destructive / Warn | `colors.warn` | #D29447 | Sheet error-banner background at 0.15 alpha (mirrors `AuthScreen.kt:281` `colors.warn.copy(alpha = 0.15f)`); warn-banner text uses `colors.ink` (NOT `warn` — keeps text legible against the soft-warn background) |

**Decline button color policy (resolves ambiguity):**

CONTEXT D-01 calls Decline a "gm.line outlined Btn". `colors.line` (#DDD4C4) is a structural divider color and is too low-contrast for an outlined button outline against the `paper` background. The correct rendering is:

- Decline `OutlinedButton` `border` color: `colors.ink` at 0.4 alpha (matches Material3 `outline` color role under the GiftMaison theme bridge; resolves to a soft warm-gray outline visually distinct from the `gm.line` divider but not as loud as full `ink`)
- Decline `OutlinedButton` text color: `colors.ink` (full opacity)
- Decline `OutlinedButton` background: transparent

If during execution the developer needs to override the M3 default, the call site MUST use these explicit values rather than `colors.line` to avoid an invisible outline.

**60/30/10 verification:**
- Dominant 60%+: `paper` (#F7F2E9) covers the inbox screen background, the sheet background, the card row backgrounds (no separate card surface), and the empty-state background — easily 70%+ of pixels.
- Secondary 30%: covered by typography ink colors (`ink` for titles, `inkSoft` for body/timestamps) which together carry the "structural secondary" weight rather than a separate surface color. The re-skin's "drop M3 Card elevation" decision (D-09) intentionally REMOVES the second-surface layer to keep the inbox visually quiet.
- Accent 10%: `accent` strictly limited to the 5 reserved elements listed above. NEVER used on body text, NEVER used on the unread-card text (the unread distinction is the small accent DOT and the `ink` vs `inkSoft` title color shift, not an accent-colored card row).

**Accent reserved for:** (a) Sheet registry-name italic display text. (b) Unread accent dot (6 dp circle) in NotificationCard. (c) Accept button container. (d) Decline button outline — REJECTED above (use ink at 0.4 alpha). (e) Wordmark period in top bar (inherited from Phase 8). NO OTHER USES.

## Interaction & State Contracts

### InviteResponseSheet (D-01, D-07)

| State | Visuals | Allowed Interactions |
|-------|---------|---------------------|
| `Idle` (default) | Hero + title + registry-name + (event-date) + Accept (enabled) + Decline (enabled). No banner. | Tap Accept → `Submitting(action=Accept)`. Tap Decline → opens AlertDialog (D-03). Swipe-dismiss → calls `onDismiss`. Esc / overlay-tap dismissable. |
| `Submitting` | Accept and Decline buttons both DISABLED. Accept button shows a 16 dp `CircularProgressIndicator` centred in place of the label if `action == Accept`; same for Decline button if `action == Decline`. No banner. | Sheet is swipe-DISMISS-LOCKED via `confirmValueChange = { !isLoading }` on the sheet state. `onDismissRequest` ignores requests in this state. The dialog from a prior Decline tap is auto-dismissed before entering Submitting (if user double-tapped). |
| `Error(action, message)` | Hero + title + registry-name + (event-date) + warn banner (gm.warn 0.15 alpha background, ink text, with Retry button) + Accept (enabled) + Decline (enabled). Banner positioned ABOVE the Accept button. | Tap Retry → `Submitting(action)` (same action that failed). Tap Accept or Decline → starts a fresh action. Swipe-dismiss ALLOWED (D-07). Esc / overlay-tap ALLOWED. |
| `AcceptedSuccess` | Sheet auto-dismisses; parent navigates to RegistryDetailKey via `onAcceptSuccess` callback (D-05). | N/A — terminal. |
| `DeclinedSuccess` | Sheet auto-dismisses; no navigation. The inbox snapshot listener removes the INVITE row automatically. | N/A — terminal. |

**Loading indicator inside button:** Material3 `Button` doesn't expose a built-in loading slot — the button content slot replaces the Text with a `CircularProgressIndicator` (16 dp size, `color = colors.accentInk` for Accept; `color = colors.ink` for Decline) when `state is Submitting && state.action == thisAction`.

**Sheet dismissal rule (D-07 disambiguation):** `Idle` and `Error` states allow ALL dismiss paths (swipe, overlay-tap, system back, Esc). `Submitting` blocks swipe and overlay-tap via `confirmValueChange = { !isLoading }`; system back also blocked via the same `onDismissRequest` guard.

### NotificationCard branching (D-11)

| Notification type | `pendingEntryKey` payload field | Tap behavior |
|-------------------|--------------------------------|---------------|
| `INVITE` | present (post-Phase-16 invite) | Opens `InviteResponseSheet` with payload-derived hero. |
| `INVITE` | absent (legacy pre-Phase-16 invite) | Falls back to `onNavigateToRegistry(payload.registryId)` — existing behaviour preserved (D-11). |
| `INVITE_ACCEPTED_SELF` / `JOINED` | N/A | `onNavigateToRegistry(payload.registryId)` — same as legacy. |
| `INVITE_ACCEPTED` (owner) | N/A | `onNavigateToRegistry(payload.registryId)` — owner navigates to their own registry. |
| `INVITE_DECLINED` (owner) | N/A | `onNavigateToRegistry(payload.registryId)` — owner can re-invite from the registry. |
| `RESERVATION_CREATED` / `ITEM_PURCHASED` / `RESERVATION_EXPIRED` / `RE_RESERVE_WINDOW` | N/A | `onNavigateToRegistry(payload.registryId)` — unchanged. |
| `UNKNOWN` (forward-compat) | N/A | No-op tap (current behaviour: tap silently ignored if `registryId` missing). |

The branching predicate MUST be extracted to a pure-Kotlin helper for testability per RESEARCH.md Wave 0 gap `NotificationCardBranchingTest.kt`.

### Unread accent-dot rendering

- 6 dp circle (`shape = CircleShape`, `background = colors.accent`).
- Positioned at the trailing edge of the title row, vertically aligned to the title's baseline-center.
- Visible only when `notification.readAtMs == null`.
- The existing 500 ms batched mark-as-read `LaunchedEffect` (line 68-79) keeps its current behaviour; the dot disappears via state change, not animation. (Per Phase 9 motion conventions, the only animated element in Phase 16 is the pulsing dot on RESERVED chips — those are NOT shown on inbox cards.)
- This REPLACES the M3 `Card` elevation-based unread distinction per D-09.

### Auto-navigation race-condition guard (Pitfall 8)

On Accept success, the parent's `onAcceptSuccess` callback navigates to `RegistryDetailKey(registryId)`. Per RESEARCH.md Pitfall 8, the local Firestore cache may not have refreshed by the time RegistryDetailScreen mounts, producing a brief "not found" flash. Phase 16 ships option (a) from the pitfall — accept the rare flash; do not pre-warm with `Source.SERVER`. If UAT surfaces visible flashes, upgrade to option (b) in a follow-up.

## Accessibility

- Sheet `Accept` button `contentDescription` derives from its text label automatically (Material3 default).
- Sheet `Decline` button same.
- Unread accent dot is purely decorative — must have `contentDescription = null`. The unread state is also conveyed via the `ink` vs `inkSoft` title color (which alone is below WCAG AA contrast distinction, so the accent dot is the redundant signal); for screen readers, the notification card root should expose an accessibility property like `"unread"` when `readAtMs == null` (planner adds via `Modifier.semantics { contentDescription = ... }` extending the existing card composition).
- `HeroImageOrPlaceholder` inside the sheet: when no cover (placeholder mode), set `contentDescription = "Registry cover placeholder for {occasion}"`. When cover present, set `contentDescription = "Cover photo for {registryName}"`. Strings get new keys under `invite_sheet_*`.
- Warn banner role: `Modifier.semantics { role = Role.Alert; liveRegion = LiveRegionMode.Assertive }` so TalkBack announces the error on appearance.
- AlertDialog: Material3 default — title + buttons are read in TalkBack order; no override needed.
- Tap targets: Accept/Decline buttons inherit M3's 48 dp minimum height. NotificationCard tap target is the entire row (full-width × ~72 dp tall after re-skin) — well above 48 dp minimum.

## Motion

Phase 16 motion is minimal — the only animated element is the existing GiftMaison pulse on Reserved chips (NOT shown on inbox cards). Specific motion contracts:

- **Sheet appearance:** Material3 `ModalBottomSheet` default slide-up. No override.
- **Sheet error-banner appearance:** No explicit animation. The banner appears/disappears via state recomposition. (If desired, the planner MAY add a 150 ms `AnimatedVisibility(enter = expandVertically() + fadeIn(), exit = shrinkVertically() + fadeOut())` for visual polish; this is non-contractual.)
- **Unread accent dot:** No animation. It disappears via state change when the 500 ms batched mark-as-read fires.
- **Auto-dismiss on success:** Material3 sheet default close animation triggers when `onDismissRequest` fires from the success LaunchedEffect.
- **Decline confirmation dialog:** Material3 `AlertDialog` default fade-scale animation. No override.

Reduced-motion: Material3 components respect system reduced-motion settings automatically; no per-component override needed.
