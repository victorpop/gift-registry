<objective>
Front-load the i18n key migration so screen plans (04 Registry, 05 Reserve banner, 06 Auth) consume `t('web_hero.section_title')` directly without each plan having to add keys mid-flight. UI-SPEC has the canonical English-Romanian copy table for ~55 keys; this plan transcribes it.

Purpose: All translation keys in one atomic commit. Easier to review, easier to revert, easier to validate parity (every key on the EN side has a RO match). Keys are additive — no removal of existing Phase 5 / 6 keys.

**Banner key shape change (v1.1 revision):** The earlier draft of this plan defined `web_reserve.banner_heading` and `web_reserve.banner_subline` as single interpolated strings with `{{itemName}}` / `{{mmss}}` / `{{retailer}}` tokens. Plan 05's StickyReserveBanner needs to wrap the item name in an italic Display span and render the MM:SS digits in a separately-testable element — single-string keys forced an opaque `.replace('  ·  ', '').replace('· ', '')` chain that was brittle to translator whitespace edits. This plan now ships the banner copy as triples mirroring the existing `web_reserve.detail_headline_*` pattern: `_pre` / `_emphasis` / `_post` for the heading, and `_pre` / `_retailer` / `_separator` / `_countdown` for the subline. Plan 05 composes the visible string from these slots without any post-processing.

Output: 4 JSON files updated. No component or page changes. The screen plans in Wave 3+ already reference `t('web_reserve.banner_heading_*')` etc.; with this plan landed, those references resolve to translated copy.
</objective>
